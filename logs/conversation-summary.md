# 本次对话结构化摘要

> 这是一份需求和决策摘要，不是逐字聊天转录。

## 1. 初始目标

用户希望使用各种 AI 工具建立个人知识体系，并进一步要求：

- 所有软件和自动化尽可能免费。
- 不依赖付费 API。
- 最差情况下完全在本机运行。
- 能自动产出文档和知识地图。
- 可以把结果放到自己的云空间分享。

## 2. 自动化要求

理想操作是用户只投入：

- 一个网址
- 一个文档
- 以后可能包括聊天记录、音视频和其他资料

系统自动完成解析、去重、摘要、分类、知识连接、搜索、地图和发布。

## 3. 专业分类理解修正

早期示意把主题、工具和来源误当成并列模块。用户明确指出需要严格的母子级专业链路。

当前已知路径：

```text
金融 / 财经 / 信用卡 / 美股
AI / Agent / 智能体
技术 / 程序员 / Java开发
```

其中 Java 开发继续展开：

```text
Java基础
JVM
并发编程
Spring生态
数据库
微服务
工程实践
```

用户说明金融、AI、技术只是当前三个大模块，未来应支持更多一级模块。

## 4. 账号聊天设想

讨论过以后连接 ChatGPT 和 Gemini 历史记录：

- 官方导出用于历史补齐。
- 本地浏览器扩展可用于新增聊天。
- 不保存密码、Cookie 或验证码。
- AI 回答不能直接视为已验证事实。

用户随后要求暂时不处理账号问题，因此该部分延后。

## 5. 在线访问

用户明确最终必须在线、随时查看知识库。

确认采用：

```text
Mac 本地处理和构建
→ 静态网站
→ Cloudflare Pages
→ Cloudflare Access 私密登录
```

这样 Mac 关机后线上已有版本仍可访问。

## 6. 当前优先级

第一阶段：

```text
本地文件或手工网址
→ 本地解析
→ 本地 AI
→ 专业母子树
→ Markdown、搜索、地图
→ 私密线上知识库
```

暂不优先：

- ChatGPT/Gemini 接入
- 批量爬虫
- RSS
- 大型向量数据库

## 7. 项目位置

用户指定全部设计、操作与后续工作流保存在：

```text
/Users/zhaoxl/ai/knowledge
```
